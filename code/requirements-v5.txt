# Training-time dependencies for the v5 pipeline (train_v5.py).
#
# The GitHub Actions workflow copies this file into the SageMaker source dir as
# requirements.txt, and the training toolkit pip-installs it before running the
# entry point.
#
# NOTE: this is deliberately NOT what the endpoint installs. train_v5.py writes
# a minimal requirements.txt (tiktoken only) into model.tar.gz/code/, because
# serving needs nothing beyond the container's torch plus the tokenizer.

torch>=2.0.0            # already present in the DLC; listed so local runs work
tiktoken>=0.5.0         # GPT-2 BPE — same vocab as the checkpoint
safetensors>=0.4.0      # reads the staged gpt2-medium weights
huggingface_hub>=0.20   # only for the fallback download when the S3 basemodel
                        # channel is absent (local runs)
datasets>=2.14,<3       # only for the fallback when the S3 training channel is
                        # absent (local runs)

# ── Why `transformers` is NOT here ──────────────────────────────────────────
# It used to be, purely to call GPT2LMHeadModel.from_pretrained() and take the
# resulting .state_dict(). That single convenience coupled this container to
# the library's torch expectations and broke the job at IMPORT time:
#
#   AttributeError: module 'torch.utils._pytree' has no attribute
#   'register_pytree_node'. Did you mean: '_register_pytree_node'?
#
# transformers kept a torch<2.2 fallback from 4.38 through ~4.52 and dropped it
# around 4.56; the PyTorch 2.1 DLC only has the underscored spelling, so any
# unpinned install eventually lands on a version that cannot import.
#
# train_v5.read_base_checkpoint() now reads config.json + model.safetensors
# directly, which is all we ever needed. safetensors has no torch-version
# coupling, the install is far smaller, and the whole class of breakage is gone.
